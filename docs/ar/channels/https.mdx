# HTTPS على عنوان IP عام

لا تنفع واجهة الويب على خادم VPS إلا إذا حصل الهاتف الذي يفتحها على القفل: فالمتصفحات لا تسمح بالإشعارات والميكروفون والتثبيت على الشاشة الرئيسية إلا على أصل HTTPS موثوق. يحصل وولفيش على تلك الشهادة بنفسه — بلا نطاق، بلا Docker، بلا وكيل عكسي، بلا أي برنامج آخر. خادم Node الخاص به هو عميل ACME ومنهي TLS.

افتح **الإعدادات ← القنوات ← واجهة الويب ← HTTPS**، اختر **Let's Encrypt**، راجع العنوان العام المكتشَف، واضغط **تفعيل HTTPS**. ومن الطرفية: `wolffish web https enable`.

## ما يحدث عند الضغط على الزر

تُعرض كل خطوة فور اكتمالها، وتأتي الخطوة الفاشلة مع الإصلاح الدقيق لنظام التشغيل الذي وُجدت عليه.

1. **العنوان العام** — يُكتشف من الإنترنت (api.ipify.org ثم icanhazip.com)، أو العنوان/النطاق الذي كتبته. تُرفض العناوين الخاصة والمحلية: لا تستطيع جهة إصدار عامة أن توثّق ما لا تصل إليه.
2. **مرتبط بهذا الجهاز** — ينبغي أن يكون العنوان على واجهة محلية؛ وإلا فالجهاز خلف NAT: وجّه المنفذين 80 و443 إليه. تحذير لا توقّف.
3. **المنفذان 80 و443 متاحان** — يُربط كلٌّ منهما ويُحرَّر. المنفذ المشغول يُسمّى مالكه والإصلاح هو إيقاف تلك الخدمة أو نقلها.
4. **مسموح بربط المنافذ المنخفضة** — انظر الملاحظات حسب النظام أدناه. يُقاس بالربط ولا يُفترض.
5. **الجدار الناري** — يُفتح `ufw` و`firewalld` على Linux وجدار Windows للمنفذين 80 و443 حين يُسمح لوولفيش بذلك؛ وإلا يُعرض الأمر. جدار مزوّد السحابة خارج الجهاز: افتح 80 و443 هناك أيضًا.
6. **قابل للوصول على المنفذ 80** — بعد تشغيل مستمع التحدي يجلب وولفيش مسار التحدي الخاص به على العنوان العام. الإخفاق خلف NAT تحذير فقط؛ فـ Let's Encrypt يتحقق من الخارج على أي حال.
7. **حساب Let's Encrypt، الطلب والتحدي، الشهادة** — طلب ACME، وإثبات HTTP-01 على المنفذ 80، وطلب الشهادة بالـ IP كاسم بديل من نوع IP، ثم التنزيل.

ثم ينتقل المتصفح الذي ضغط الزر إلى `https://<العنوان>` بعد عدٍّ تنازلي من ثلاث ثوانٍ.

## المستمعات

| المنفذ              | يقدّم                   | بعد تفعيل HTTPS                                                                           |
| ------------------- | ----------------------- | ----------------------------------------------------------------------------------------- |
| 443                 | التطبيق كاملًا عبر TLS  | —                                                                                         |
| 80                  | مسار تحدي ACME          | كل شيء آخر يُعاد توجيهه (301) إلى HTTPS                                                   |
| 8787 (منفذ التطبيق) | التطبيق كاملًا عبر HTTP | المتصفحات القادمة بالعنوان تُعاد (301) إلى HTTPS؛ والصفحة المفتوحة تحتفظ بمقبسها حتى تتبع |

كلا منفذي TLS قابلان للضبط (**خيارات متقدمة** على البطاقة، أو `channels.web.httpsPort` و`channels.web.httpPort`). ولا يُسقِط أي شيء في HTTPS منفذ التطبيق أبدًا: فهو المنفذ الذي يتصل به المتصفح الذي ضغط الزر، والذي تُقدَّم عليه اللوحة التي تشرح الفشل.

## شهادة الأيام الستة

يصدر Let's Encrypt شهادات عناوين IP تحت الملف الشخصي **قصير العمر** فقط: نحو 160 ساعة. لذلك يجدّد وولفيش وحده:

- فحص كل **6 ساعات**، ومرة عند الإقلاع؛
- تجديد عندما يتبقى أقل من **72 ساعة** (أو أقل من ثلث العمر — 30 يومًا لشهادة نطاق مدتها 90 يومًا)؛
- بعد الفشل، إعادة المحاولة بعد 15 دقيقة تتضاعف حتى 6 ساعات مع تشويش عشوائي؛
- تُبدَّل الشهادة الجديدة في المستمع العامل (`setSecureContext`) — دون إعادة تشغيل أبدًا؛
- تُسجَّل كل محاولة (الوقت، النتيجة، المدة، الخطأ)، وتُعرض آخر 20 على البطاقة وبالأمر `wolffish web https`.

النطاق في الحقل الاختياري يحصل على شهادة عادية مدتها 90 يومًا من المسار نفسه، بلا ملف شخصي.

تحتفظ الميزة بآلة حالات صغيرة محفوظة بجانب الشهادة تحت `~/.wolffish/workspace/web/tls/`: `disabled → preflight → issuing → active ⇄ renewing`، و`error` تعني أن لا شهادة موثوقة تُقدَّم (بل البديلة الموقّعة ذاتيًا، فتبقى اللوحة قابلة للوصول). وفشل التجديد بينما الشهادة الحالية صالحة ليس حالة خطأ: يستمر الجهاز في التقديم ويأتي الفحص التالي أبكر.

يجب أن يعمل وولفيش كل ثلاثة أيام على الأقل ليحدث التجديد. **الإعدادات ← القنوات ← CLI ← البدء تلقائيًا** يسجّله لدى مشرف النظام: systemd (وحدة مستخدم، `Restart=always`، مع البقاء ليبدأ عند الإقلاع)، وlaunchd (`KeepAlive`)، وجدولة المهام (عند تسجيل الدخول، مع إعادة التشغيل عند الفشل). و**إعادة تشغيل وولفيش** على البطاقة يفرّغ الأدوار الجارية ويعيد تشغيل العملية فتعود تحت ذلك المشرف.

## المتطلبات حسب النظام

<Tabs>
  <Tab title="Linux (VPS)">
    تحتاج المنافذ دون 1024 إلى صلاحية. بصفتك **root** لا يلزم شيء. وبمستخدم آخر، أحد الخيارين:

    ```bash
    sudo sysctl -w net.ipv4.ip_unprivileged_port_start=80 && echo 'net.ipv4.ip_unprivileged_port_start=80' | sudo tee /etc/sysctl.d/60-wolffish-ports.conf
    ```

    ```bash
    sudo setcap 'cap_net_bind_service=+ep' /opt/Wolffish/wolffish   # يُكرَّر بعد كل تحديث
    ```

    يكتب المثبّت وحدة systemd للمستخدم، حيث لا يمكن تطبيق `AmbientCapabilities=CAP_NET_BIND_SERVICE`؛ هذا السطر لوحدة على مستوى النظام تديرها بنفسك. افتح 80 و443 في `ufw` أو `firewalld` (يحاول الفحص المسبق ذلك)، وفي جدار المزوّد أو مجموعة الأمان.

  </Tab>
  <Tab title="macOS">
    لا تسمح إصدارات macOS الحديثة إلا لـ root بربط المنافذ دون 1024 (يقيس الفحص المسبق ذلك ولا يفترضه). وجّهها بـ pf إلى منافذ يستطيع وولفيش ربطها، ثم أشر إليها:

    ```bash
    printf 'rdr pass inet proto tcp from any to any port 80 -> 127.0.0.1 port 8080\nrdr pass inet proto tcp from any to any port 443 -> 127.0.0.1 port 8443\n' | sudo tee /etc/pf.anchors/wolffish
    printf 'rdr-anchor "wolffish"\nload anchor "wolffish" from "/etc/pf.anchors/wolffish"\n' | sudo tee -a /etc/pf.conf && sudo pfctl -ef /etc/pf.conf
    wolffish settings set channels.web.httpsPort 8443 && wolffish settings set channels.web.httpPort 8080
    ```

    pf متوقف افتراضيًا، ويسأل جدار التطبيقات مرة واحدة عند أول استماع.

  </Tab>
  <Tab title="Windows">
    لا قاعدة للمنافذ المميزة. يضيف الفحص المسبق قاعدة جدار Windows حين يُشغَّل من صدفة مرتفعة الصلاحية؛ وإلا يطبع سطر `New-NetFirewallRule` لتشغيله كمسؤول. تُسجَّل المهمة المجدولة عبر PowerShell مع إعادة التشغيل عند الفشل.
  </Tab>
</Tabs>

## من الطرفية

```bash
wolffish web https                      # الحالة، العنوان، المُصدِر، الانتهاء، الفحص التالي، السجل
wolffish web https enable               # الزر؛ --ip A أو --domain D أو --staging
wolffish web https renew                # الآن، مرة في الدقيقة على الأكثر
wolffish web https disable              # العودة إلى HTTP على منفذ التطبيق
wolffish web restart                    # إعادة تطبيق الإعدادات
wolffish restart                        # إعادة تشغيل العملية كلها
wolffish settings set channels.web.acmeDirectory staging   # مفتاح الاختبار المخفي
```

يستخدم `--staging` (وإعداد الدليل) بيئة Let's Encrypt التجريبية: شهادات غير موثوقة بحدود معدل سخية، لتجربة المسار دون استهلاك حصة الإنتاج. يسمح الإنتاج بخمس شهادات متطابقة أسبوعيًا.

## استكشاف الأخطاء

| العرض                                                      | السبب                                 | الإصلاح                                                                                                                                |
| ---------------------------------------------------------- | ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| "port 80 is already in use (nginx …)"                      | خادم ويب آخر                          | أوقفه، أو دعه يوكّل إلى وولفيش واستخدم **شهادتي**                                                                                      |
| "binding port 443 was refused (EACCES)"                    | منافذ مميزة                           | الملاحظات حسب النظام أعلاه؛ تعرض الخطوة الأوامر الدقيقة                                                                                |
| "validation failed — the CA could not reach the challenge" | المنفذ 80 غير قابل للوصول من الإنترنت | توجيه NAT، جدار المضيف، جدار المزوّد؛ ينبغي أن يجيب `curl http://<ip>/.well-known/acme-challenge/x` من مكان آخر بـ `no such challenge` |
| `is a private address`                                     | اكتُشف أو كُتب عنوان شبكة محلية       | استخدم العام، أو اسم مضيف يشير إلى هنا                                                                                                 |
| `too many certificates already issued`                     | حد معدل الإنتاج                       | انتظر، أو اختبر بـ `--staging`                                                                                                         |
| المتصفح لا يزال يحذّر بعد التفعيل                          | تُقدَّم البديلة الموقّعة ذاتيًا       | تعرض البطاقة **خطأ** مع السبب؛ أصلح ثم **أعد المحاولة**                                                                                |
| انتهت الشهادة                                              | لم يعمل وولفيش ثلاثة أيام             | شغّله؛ يجدّد عند الإقلاع. سجّل الخدمة كي لا يتكرر                                                                                      |
| `wait a minute between attempts`                           | التفعيل/التجديد محدودا المعدل         | انتظر 60 ثانية                                                                                                                         |
