# ابحث عن مشكلتك

المشاكل الشائعة وحلولها. ابدأ بالمشكلة التي تتطابق مع أعراضك.

<AccordionGroup>
  <Accordion title="دورٌ يعلّق بلا ردٍّ ولا خطأ">
    **الأعراض**: الدور يعمل، والدوّام قائم، ولا يصل شيء — لدقائق.

    يستطيع مزوّدُ نموذجٍ أن يقبل الطلب ثمّ **لا يقول شيئاً البتّة**. فاستدعاءٌ واحد قيس في أثناء التطوير جلس صامتاً عشر دقائق ثمّ أعاد رمزاً واحداً؛ وآخرُ أربعَ دقائق ولم يُعِد شيئاً. وكان الدور يعلّق ببساطة، لأنّ **الاتّصال المفتوح الذي لا يتكلّم يبدو تماماً كالذي يفكّر**.

    ومنذ **الإصدار 1.0.299** صار وولفيش يترصّد ذلك: **خمس دقائق بلا أيّ استجابة** فيُسقَط الطلب، وينتهي الدور، وتنال بطاقةً تقول ذلك.

    ولا تُعاد المحاولة **تلقائياً أبداً**، لأنّ خمس دقائق من الصمت **قرارُك أنت** — فتعرض البطاقة زرّ **متابعة**، يواصل من حيث توقّفت الأمور بالضبط. ولا يضيع شيء: فالملفّات المكتوبة ونتائجُ الأدوات والخطّةُ حتى تلك اللحظة كلُّها قائمة، والملاحظةُ التي تستأنف المحادثة تظهر **سطراً هادئاً في الخيط**، لا شيئاً قلتَه أنت.

    <Note>
      **النماذج المحلّية مستثناة.** فـOllama لا يقول شيئاً وهو يقيّم طلباً طويلاً، وعلى جهازٍ بطيء قد يتجاوز ذلك وحده خمس دقائق — فلا يقطع هذا المترصّدُ نموذجاً محلّيّاً أبداً. وإن علّق دورٌ محلّيّ، فالفحوصُ في القسم التالي هي المعنيّة.
    </Note>
  </Accordion>

  <Accordion title="وولفيش لا يستجيب على الإطلاق">
    **الأعراض**: تكتب رسالة ولا يحدث شيء. لا استجابة، لا خطأ.

    **تحقق من هذه بالترتيب:**

    1. **حالة المزود** — افتح الإعدادات وتأكد أن مزود LLM الخاص بك مُهيأ ويمكن الوصول إليه. إذا كنت تستخدم مزوداً سحابياً (OpenAI أو Anthropic)، تحقق من صفحة حالتهم.

    2. **هل Ollama يعمل** — إذا كنت تستخدم نموذجاً محلياً، تأكد أن Ollama يعمل:
       ```bash
       curl http://localhost:11434/api/tags
       ```
       إذا انتهت المهلة، شغّل Ollama: `ollama serve`

    3. **سجلات التطبيق** — تحقق من سجلات Electron للأعطال:
       ```bash
       ls -lt ~/.wolffish/logs/
       cat ~/.wolffish/logs/main.log
       ```
       ابحث عن استثناءات غير مُعالجة أو أخطاء اتصال.

    4. **سجل الأحداث** — إذا بدا التطبيق متجاوباً لكن LLM لا يرد، تحقق مما إذا كانت الأحداث تُطلق:
       ```bash
       tail -20 ~/.wolffish/workspace/brain/corpus/$(date +%Y-%m-%d).log.md
       ```
       إذا رأيت `message.received` لكن لا `llm.response`، فاستدعاء المزود معلق أو فاشل.

  </Accordion>

  <Accordion title="الوكيل لا يستخدم قدرتي">
    **الأعراض**: أنشأت قدرة لكن وولفيش لا يستخدمها أبداً.

    **كيف يعمل الاكتشاف الآن**: مجموعة أساسية من القدرات تُحمّل دائماً؛ وكل ما عداها يظهر كسطر واحد في فهرس `<capabilities>` داخل الموجّه، ويُحمّل عند الطلب عندما يستدعي النموذج `tool_search` (الذي يطابق أسماء القدرات وأوصافها ومُحفزاتها وأسماء أدواتها) أو يستدعي إحدى أدواتها مباشرة.

    **تحقق من هذه:**

    1. **أنها في الفهرس** — أرسل أي رسالة، ثم افتح أحدث لقطة تصحيح:
       ```bash
       ls -t brain/prefrontal/.debug/ | head -1
       ```
       انظر في قسم `<capabilities>`. إذا لم تكن قدرتك مُدرجة إطلاقاً، فقد فشل تحليل SKILL.md الخاص بها — تحقق من الواجهة (YAML تالف، حقول مطلوبة مفقودة).

    2. **اجعلها قابلة للعثور** — `tool_search` بحث بالمصطلحات. أعطِ SKILL.md اسماً (`name`) ووصفاً (`description`) واضحين، وأضف `triggers` تغطي الكلمات التي ستستخدمها طبيعياً:
       ```yaml
       triggers:
         - "deploy"
         - "push to production"
         - "release"
       ```

    3. **اطلبها صراحةً** — قل لـ وولفيش "use tool_search to find a deployment capability". إذا حمّلها وشغّلها، فالإضافة سليمة وكل ما يلزم هو شحذ الأوصاف.

    4. **ثبّتها** — إذا كان ينبغي أن تكون القدرة محمّلة *دائماً* (تُشحن مخططاتها مع كل طلب)، أضفها إلى `pinnedCapabilities` في `config.json`:
       ```json
       {
         "pinnedCapabilities": ["my-capability"]
       }
       ```

  </Accordion>

  <Accordion title="استدعاءات الأدوات تُحظر دائماً">
    **الأعراض**: كل استدعاء أداة يُطلق تأكيد أمان أو يُرفض.

    **تحقق من هذه:**

    1. **danger_patterns في SKILL.md** — يفحص `amygdala` معاملات الأداة مقابل تعبيرات `danger_patterns` النمطية المُعرّفة في SKILL.md الخاص بالقدرة. إذا كانت أنماطك واسعة جداً، ستتطابق مع كل شيء:
       ```yaml
       danger_patterns:
         - "rm\\s+-rf"        # Good: specific
         - "rm"               # Bad: matches "format", "inform", etc.
       ```

    2. **confirm_patterns** — هذه تتطلب تأكيد المستخدم لكن لا تحظر. إذا أردت تشغيل الأداة بدون سؤال، أزل النمط المطابق من `confirm_patterns`.

    3. **إعداد التجاوز** — للتطوير، يمكنك تعطيل تأكيدات الأمان في الإعدادات. هذا يتخطى بوابة amygdala بالكامل.

    <Warning>
    عطّل الأمان في التطوير فقط. في الاستخدام العادي، بوابة الأمان تمنع العمليات المدمرة.
    </Warning>

  </Accordion>

  <Accordion title="الذاكرة تبدو خاطئة أو قديمة">
    **الأعراض**: يشير وولفيش إلى معلومات خاطئة أو قديمة أو من سياق غير صحيح.

    **أصلحها مباشرة:**

    1. **اقرأ ملف الحلقة** — الحلقات هي Markdown عادي. ابحث عن الذاكرة المعيبة:
       ```bash
       grep -r "wrong information" brain/hippocampus/episodes/
       ```

    2. **عدّلها أو احذفها** — افتح ملف الحلقة وأصلح المحتوى، أو احذف الملف بالكامل. الحلقات مجرد Markdown — عدّلها مثل أي ملف آخر. وينطبق الأمر نفسه على ملفات المعرفة تحت `brain/hippocampus/knowledge/` — فالحقائق الدائمة كثيراً ما تعيش هناك.

    3. **الفهرس يلحق بك** — لا حاجة لإعادة بناء يدوية: مراقب الملفات يعيد فهرسة الملفات المعدّلة أثناء عمل وولفيش، وكل إقلاع يجري مقارنة تزايدية. إذا بقي الفهرس يبدو خاطئاً، أجبره على إعادة بناء كاملة:
       ```bash
       rm ~/.wolffish/workspace/brain/cortex.db*
       ```
       عند التشغيل التالي، يعيد cortex فهرسة مساحة العمل بأكملها (نحو ثانية واحدة، حتى للجيجابايتات).

  </Accordion>

  <Accordion title="السياق كبير جداً / الاستجابات بطيئة">
    **الأعراض**: يستغرق وولفيش وقتاً طويلاً للاستجابة، أو ترى تحذيرات ميزانية الرموز.

    موجّه النظام لمحادثة جديدة يبلغ نحو 5 آلاف رمز بحكم التصميم، والمحادثات الطويلة تُطوى تلقائياً إلى ملخص متجدد مع الذيل الحرفي الأخير — لذا فالسياق المتضخم هو الاستثناء لا القاعدة. حين يحدث:

    1. **تحذيرات hypothalamus** — ابحث عن أحداث الصحة:
       ```bash
       grep "health" brain/corpus/$(date +%Y-%m-%d).log.md
       ```
       التحذيرات حول استخدام الرموز تعني أن نافذة السياق ممتلئة تقريباً.

    2. **تحقق من ترويسة لقطة التصحيح** — يُظهر `estimated tokens` في أعلى أحدث لقطة حجم الموجّه. إذا كان أعلى بكثير من نحو 5 آلاف، فالمتهم المعتاد ملف ضخم يُضمَّن دائماً: ملف `soul.md` أو `user.md` أو `agents.md` كبير يهبط في كل موجّه.

    3. **راقب عدّاد السياق** — بجوار حقل إدخال المحادثة، البسط هو الرموز التي حاسبك عليها المزود في آخر طلب، والمقام هو نافذة السياق الكاملة للنموذج. نتائج الأدوات المفردة الكبيرة (قراءة ملف عملاق، جلب صفحة ضخمة) تضخّم الدور مؤقتاً؛ أما نتائج الأدوات الكبيرة التي فقدت حداثتها فتُستبدل في الأدوار اللاحقة ببدائل مختصرة تحمل مؤشر استرجاع.

    4. **القدرات المثبّتة** — كل قدرة في `pinnedCapabilities` تشحن مخططات أدواتها الكاملة مع كل طلب. ثبّت باقتصاد؛ فـ `tool_search` يحمّل البقية عند الطلب (بحد أقصى 10 قدرات غير أساسية نشطة لكل محادثة).

  </Accordion>

  <Accordion title="Telegram / WhatsApp لا يتصل">
    **الأعراض**: القناة تظهر كمنفصلة، الرسائل لا تُستقبل.

    **لـ Telegram:**
    1. تأكد أن رمز البوت في الإعدادات صحيح
    2. تحقق من الاتصال بالإنترنت
    3. ابحث عن أخطاء الاتصال:
       ```bash
       grep "telegram\|channel" ~/.wolffish/logs/main.log
       ```
    4. بوتات Telegram تتطلب الاستقصاء — إذا كان وولفيش غير متصل، يعيد الاتصال تلقائياً عند إعادة التشغيل

    **لـ WhatsApp:**
    1. يجب مسح رمز QR في الإعدادات بهاتفك
    2. تنتهي الجلسة إذا كان هاتفك غير متصل لأكثر من 14 يوماً — أعد مسح رمز QR
    3. تحقق من أخطاء الجلسة في السجلات:
       ```bash
       grep "whatsapp\|wa-web" ~/.wolffish/logs/main.log
       ```

  </Accordion>

  <Accordion title="الإضافة تُطلق أخطاء">
    **الأعراض**: إضافة قدرة تفشل في التحميل أو الأدوات تُخطئ أثناء التشغيل.

    **تحقق من هذه:**

    1. **بنية التصدير** — `plugin/index.mjs` يجب أن يُصدّر كائناً افتراضياً:
       ```javascript
       export default {
         init(context) { ... },
         tools: { ... }
       }
       ```

    2. **أسماء الأدوات تتطابق** — أسماء الأدوات في الإضافة يجب أن تتطابق تماماً مع الأسماء المُعلنة في قسم `tools:` في واجهة SKILL.md.

    3. **المعاملات تتطابق مع المخطط** — مخطط JSON في SKILL.md يجب أن يتطابق مع ما تتوقعه دالة الإضافة. عدم تطابق الأنواع يسبب فشلاً صامتاً.

    4. **تحقق من سجل التطبيق** — أخطاء تحميل القدرات تهبط في سجل التطبيق:
       ```bash
       grep -i "skill\|capability\|plugin" ~/.wolffish/workspace/logs/$(date +%Y-%m-%d).log
       ```
       رسالة الخطأ عادة تشير إلى المشكلة بالضبط (تصدير مفقود، خطأ صياغة، استيراد تالف).

  </Accordion>

  <Accordion title="cortex.db تالف">
    **الأعراض**: البحث لا يعمل، استرجاع الذاكرة يفشل، أخطاء تذكر SQLite أو FTS5.

    **الإصلاح**: احذف قاعدة البيانات (مع رفيقيها `-shm`/`-wal`). يعيد وولفيش بناءها من الملفات المصدرية عند التشغيل التالي:
    ```bash
    rm ~/.wolffish/workspace/brain/cortex.db*
    ```

    ثم أعد تشغيل وولفيش. يعيد cortex فهرسة كل شيء — الحلقات والمعرفة والمحادثات والمهام والسجلات والاستخدام والمخرجات — في نحو ثانية واحدة، حتى لمساحة عمل بعدة جيجابايتات. الإقلاع العادي (بدون حذف) يجري مقارنة تزايدية فقط، تستغرق أجزاء من الثانية.

    <Info>
    `cortex.db` هو مخرج مُشتق — يمكن إعادة بنائه دائماً من الملفات على القرص. لن تفقد بيانات أبداً بحذفه.
    </Info>

  </Accordion>

  <Accordion title="وولفيش يستخدم مساحة قرص كبيرة">
    **الأعراض**: استخدام القرص يزداد بمرور الوقت، خاصة في `~/.wolffish/`.

    **تحقق من هذه المواقع:**

    1. **ذاكرة التخزين المؤقت لـ Chromium** — المتصفح المُضمن يُخزّن بقوة:
       ```bash
       du -sh ~/.wolffish/runtime/
       ```
       آمن للحذف: `rm -rf ~/.wolffish/runtime/Cache/`

    2. **سجلات الأحداث القديمة** — يجب أن تُنظف تلقائياً بعد 7 أيام، لكن تحقق:
       ```bash
       ls -la ~/.wolffish/workspace/brain/corpus/*.log.md
       ```

    3. **تراكم الحلقات** — المثيلات طويلة التشغيل تراكم حلقات. راجع وقلّم القديمة:
       ```bash
       du -sh ~/.wolffish/workspace/brain/hippocampus/episodes/
       ls ~/.wolffish/workspace/brain/hippocampus/episodes/ | wc -l
       ```

    4. **لقطات التصحيح** — محدودة بأحدث 50 لقطة (تُزال الأقدم تلقائياً بالتناوب)، لكن تحقق:
       ```bash
       ls ~/.wolffish/workspace/brain/prefrontal/.debug/ | wc -l
       ```

  </Accordion>

  <Accordion title="كيفية إعادة تعيين كل شيء (الخيار النووي)">
    إذا لم ينفع أي شيء آخر وتريد البدء من الصفر:

    ```bash
    rm -rf ~/.wolffish/
    ```

    <Warning>
    هذا يحذف جميع الإعدادات والذكريات والحلقات والقدرات والسجلات. سيُشغل وولفيش إعداد التشغيل الأول مرة أخرى. افعل هذا فقط إذا كنت مستعداً لخسارة كل شيء.
    </Warning>

    لإعادة تعيين أقل تدميراً، احذف أجزاء محددة فقط:
    - `rm ~/.wolffish/workspace/brain/cortex.db*` — إعادة بناء فهرس البحث فقط
    - `rm -rf ~/.wolffish/workspace/brain/hippocampus/episodes/` — مسح جميع الذكريات
    - `rm -rf ~/.wolffish/workspace/brain/corpus/` — مسح سجلات الأحداث
    - `rm -rf ~/.wolffish/workspace/brain/prefrontal/.debug/` — مسح لقطات التصحيح

  </Accordion>
</AccordionGroup>

## الحصول على المساعدة

لم يعد وولفيش قيد التطوير، فلا قناة دعم، و[متتبّع المشاكل](https://github.com/younes-alturkey/wolffish/issues) غير مراقَب بنشاط. صفحات التصحيح أعلاه هي طريق الدعم: كل دور يترك لقطة تصحيح وسجل أحداث وملف مهمة على القرص، والشفرة ملكك تقرأها وتصلحها.

<Tip>
  عند تقديم تقرير خلل، أرفق: 1. لقطة التصحيح من الدور الفاشل 2. القسم المعني من
  سجل الأحداث 3. ملف المهمة (إذا كانت أداة مُتضمنة) 4. ملف `config.json` الخاص
  بك (أخفِ مفاتيح API)
</Tip>
