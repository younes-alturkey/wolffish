# ماذا يخزّن config.json

يقع في `brain/config.json`، ويخزّن هذا الملف إعدادات على مستوى التطبيق. يُقرأ عند بدء التشغيل ويمكن تعديله عبر واجهة الإعدادات أو بتحرير الملف مباشرة.

## حقول التكوين

```json
{
  "mind": {
    "provider": "deepseek",
    "model": "deepseek-v4-pro"
  },
  "providers": {
    "deepseek": {
      "apiKey": "",
      "model": "deepseek-v4-pro"
    },
    "anthropic": {
      "apiKey": "",
      "model": "claude-sonnet-4-20250514"
    },
    "openai": {
      "apiKey": "",
      "model": "gpt-4o"
    },
    "ollama": {
      "host": "http://localhost:11434",
      "model": "gemma3:4b"
    }
  },
  "pinnedCapabilities": ["github"],
  "language": "en"
}
```

## مرجع الحقول

| الحقل | الوصف |
|---|---|
| `mind.provider` | مزود نموذج اللغة النشط: `deepseek` أو `anthropic` أو `openai` أو `ollama` |
| `mind.model` | اسم النموذج النشط |
| `providers.deepseek.apiKey` | مفتاح API لـ DeepSeek |
| `providers.anthropic.apiKey` | مفتاح API لـ Anthropic |
| `providers.openai.apiKey` | مفتاح API لـ OpenAI |
| `providers.ollama.host` | عنوان خادم Ollama (افتراضيًا: `http://localhost:11434`) |
| `mcp.servers[]` | [خوادم MCP](/ar/integrations/mcp) المتصلة — المعرّف والاسم ووسيلة النقل (`stdio`/`http`) والأمر أو الرابط ومتغيرات البيئة وحالة التفعيل ورموز OAuth للخوادم البعيدة الموقَّع دخولها. تديرها الإعدادات ← بروتوكول سياق النماذج وأدوات `mcp_*` في المحادثة |
| `pinnedCapabilities` | قدرات إضافية تُرسل مخططات أدواتها مع **كل** طلب، فوق المجموعة الأساسية المدمجة. مقبض الضبط لسطح الأدوات الرشيق — كل ما عداها على بُعد استدعاء `tool_search` واحد. لا واجهة له؛ حرّر هذه المصفوفة يدويًا (مثل `["github", "google"]`) |
| `language` | لغة الواجهة: `en` (الإنجليزية) أو `ar` (العربية) |

## اختيار النموذج

يعمل وولفيش على نموذج مُختار صراحةً — لا يوجد احتياطي تلقائي. تختار نموذج **الدماغ** لديك (المزوّد + النموذج) من مبدّل النماذج بجوار حقل الإدخال، وهو النموذج الذي يعمل. النموذج الذي تختاره هو من يجيب؛ وإن فشل، يفشل الدور بدل التوجيه بصمت إلى مزوّد آخر.

اختياريًا، انقل المحادثة إلى **وضع سير العمل** (`llm.mode: "workflow"`، يُبدَّل من صفّ شرائح **الوضع** داخل بطاقة النموذج بجوار حقل الإدخال) — فيستطيع كل دور عندها تخطيط مراحل وإطلاق وكلاء متوازين، والقائد يختار نموذج كل وكيل من مزوّديك الموصولين. راجع [وضع سير العمل](/ar/configuration/workflow-mode) لكيفية عمل ذلك. وحتى عندها لا يوجد تدرّج — كل نموذج يعمل اختير صراحةً، منك أو من القائد.

جميع المزودين اختياريون — تحتاج فقط من تختارهم فعلًا. لاستخدام Ollama، اختره نموذج دماغك؛ لا يوجد انتقال تلقائي إلى المحلي.

<Info>
  تُخزَّن مفاتيح API بنص صريح في config.json. هذا متعمَّد — وولفيش تطبيق يعمل محليًا أولًا ومساحة عملك ملكك. إذا كنت تستخدم git لإدارة إصدارات مساحة عملك، أضف `brain/config.json` إلى `.gitignore`.
</Info>
